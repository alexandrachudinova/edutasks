Учебная задача: Оптимизация производительности и устранение архитектурных дефектов в .NET API

Условие задачи (Проблемное исходное состояние)
Бэкенд-сервис на ASP.NET Core демонстрирует деградацию производительности под нагрузкой: время отклика эндпоинта получения списка заказов (GET /api/orders) превышает 2 секунды при 50 одновременных запросах. В консоли отладки зафиксированы сотни идентичных SQL-запросов, а мониторинг показывает высокий процент загрузки процессора из-за частого срабатывания сборщика мусора (GC) и истощения пула потоков (Thread Starvation).

Диагностика первопричин

Проблема N+1 в EF Core: Сущности выгружались базовым методом без связей, после чего в цикле foreach для каждой строки запрашивались дочерние данные через ORM.

Блокировка пула потоков: В сервисе использовался синхронный вызов .Result у асинхронных операций вместо сквозного применения async/await.

Ошибки DI: Контекст базы данных (DbContext) или тяжелые сервисы были зарегистрированы с нарушением изоляции жизненных циклов, порождая лишний мусор в оперативной памяти.

Пошаговое решение (Шаблон для выполнения)

Шаг 1. Исправление конфигурации жизненных циклов в Program.cs
Зарегистрируйте DbContext и репозитории с правильным временем жизни (Scoped), чтобы избежать утечек памяти и чрезмерной нагрузки на кучу GC: before_optimisation
